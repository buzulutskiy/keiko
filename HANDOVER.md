## Что это и зачем

Кэйко (稽古 — «регулярная практика») — личный трекер занятий на двоих: Антон и его жена
Диана. Пианино, книги, курс пастели, видео. Приложение отвечает на один вопрос: чем
заняться сейчас и что дальше, — и записывает, что уже сделано.

Три установки, которые определяют почти все решения в интерфейсе:

- **Никаких серий и штрафов.** Серия («10 дней подряд!») превращает пропуск в потерю,
  поэтому её нет на видном месте. Пропуск — не провинность.
- **Никаких практик, ритуалов и заданий.** Приложение не выдаёт упражнений и не
  уговаривает. Нужен минимализм без принуждения.
- **Материалов в коде нет.** Ни одной книги, пьесы или награды в репозитории. Всё
  содержимое живёт в приватных гистах владельца. Пустое приложение без токена — это
  нормальное состояние, а не ошибка.

Живёт на GitHub Pages: <https://buzulutskiy.github.io/keiko/>, ставится на телефон как PWA.

## Устройство проекта

Сборки нет. Совсем. Файлы отдаются как есть:

| Файл | Что внутри |
|---|---|
| `index.html` | вся вёрстка и все стили (~3600 строк): тема, экраны, оверлеи, шторка |
| `app.js` | всё приложение одним файлом (~13 000 строк), разделено комментариями `/* ═══ Раздел ═══ */` |
| `sw.js` | service worker: кэш оболочки `keiko-v<N>`, стратегия «сначала кэш, потом тихое обновление» |
| `version.json` | версия на сервере; приложение сверяет её и показывает баннер «Есть новая версия» |
| `manifest.webmanifest`, `icon-*.png`, `splash-*.png` | PWA-обвязка |
| `howler.min.js` | единственная внешняя библиотека — звук материала |
| `serve.py` | локальный сервер: `python3 serve.py 8473` |
| `tools/*.py` | скрипты заливки содержимого в гисты (см. ниже) |

Код на русском: имена функций местами кириллицей (`рисуйКлуб`, `рисуйРазговор`),
комментарии — всегда. Комментарий объясняет **почему так**, а не что делает строка;
многие из них — запись прошлых ошибок. Не переписывай их в «нейтральный» стиль.

Service worker чистит **только** свои прошлые версии оболочки (`/^keiko-v\d+$/`).
Остальные Cache Storage — обложки, звук, видео разбора, записи игры — данные
пользователя, их трогать нельзя.

## Где лежат данные: четыре гиста

Все приватные (secret). Токен GitHub с scope `gist` вводится один раз в настройках и
лежит в `localStorage` (`keiko-cfg-v1`, общий для профилей).

**1. Данные профилей** — `67442ecb9e18c230a93fad886b712c4f`

- `keiko-anton.json`, `keiko-diana.json` — по файлу на профиль.
- `prokachka.json` — общий файл первой версии, читается только для переезда.

**2. Каталог** — `8a3a280b21390e3b32569913f9f3cabe`

| Файл | Что |
|---|---|
| `keiko-catalog.json` | профили, материалы: награды, тексты наград, карточки знаний |
| `article-<id>.json` | разборы, вопросы и комментарии одного материала — грузится по требованию |
| `keiko-practice.json` | по-нотный разбор пьес: части, подсказки по тактам, точки прогонов |
| `keiko-taxonomy.json` | скелет карты знаний |
| `keiko-categories.json` | привязка материала к листу карты |
| `keiko-audio-envelopes.json` | заранее посчитанные огибающие звука для фоновых волн |
| `cover-<id>.txt` | обложка материала, `data:image/jpeg;base64,…` |
| `audio-<id>.txt` | звук материала |
| `art-<id>.txt` | иллюстрация к статье |

Обложки и звук — отдельными файлами намеренно: иначе один файл гиста разрастается и
каждая синхронизация тащит мегабайты.

**3. Архив копий** — гист с описанием «Кэйко — архив копий», заводится сам. Раз в
неделю кладёт снимок данных: файл на месяц, последние 12.

**4. Вложения** — гист «Кэйко — записи собственной игры»: записи игры и фотографии
работ, привязанные к мыслям. Адрес хранится в самих данных (`takesId`), иначе на
втором телефоне вложения неоткуда взять.

## Синхронизация

Устройство — источник правды, гист — копия. Порядок работы:

1. Отметка пишется в `localStorage` (`keiko-data-v1-<профиль>`) и **перечитывается**:
   место в хранилище кончается молча.
2. `schedulePush()` откладывает отправку; `syncNow()` скачивает файл профиля,
   сливает и отправляет обратно PATCH-ом **только свой файл** — чужой профиль в гисте
   не трогается.
3. Условный запрос по ETag: `cfg.gistEtagBy[profileId]`. На 304 сравнивать не с чем,
   поэтому рядом лежит отпечаток отправленного — `cfg.syncNormBy[profileId]`.
   **И то и другое — по профилю.** Общий ETag однажды стоил Диане потерянных данных.
4. Каталог сверяется не реже раза в 5 минут, тоже по ETag. Раньше стояли сутки — и
   новая карточка доезжала до телефона к следующему дню.

Правила слияния (`syncNow`):

- Списки (`entries`, `books`, `thoughts`, `wishes`, `gut`, `pills`, `takes`, `freezes`,
  `archive`) — `mergeLists` по `id`, побеждает больший `updatedAt`. Удаление —
  флаг `deleted`, не вырезание.
- Своды (`weekGoal`, тема, `talks`) — по собственной отметке времени (`goalAt`,
  `themeAt`, `talksAt`), а не по штампу файла.
- `club` (прочитанные разборы) — объединение: отметка не должна пропасть.
- `practice` (ход разбора пьес) — `mergePrac`, отметка времени ставится в `pracStamp`
  при сохранении.
- `daily.seen` — складывается, а не заменяется, иначе мысли идут по второму кругу.

## Данные профиля

Что уезжает в гист — см. `exportData()`. Кратко:

| Поле | Что |
|---|---|
| `active` | какой трек открыт: `book` / `piano` / `pastel` / `watch` |
| `book` | `{books[], activeBook, entries[]}` — определения книг живут в данных, не в каталоге |
| `piano` | `{pieces[], activePiece, entries[]}` |
| `pastel` | `{course, entries[]}` |
| `watch` | `{videos[], activeVideo, entries[]}` |
| `practice` | ход разбора: `{pieceId: {done, session, at}}`, у курса — `practice.pastel` |
| `thoughts` | мысли и события ленты (у события есть `event`, у мысли — нет) |
| `wishes` | «Захотелось» |
| `gut`, `pills` | разделы одного профиля (см. ниже) |
| `club`, `talks` | прочитанные разборы и выбранные версии ответов |
| `archive` | пройденные материалы (полка) |
| `takes`, `takesId` | вложения и адрес их гиста |
| `hidden` | что убрано с главной |
| `freezes` | периоды паузы: отпуск, болезнь |
| `weekGoal` | сколько дней в неделю заниматься чем угодно |
| `daily` | мысль дня: дата, показанные, выключатель |

Записи занятий (`entries`) устроены одинаково: `{id, date, note?, createdAt, updatedAt}`
плюс своё поле трека — `page`/`spans` у книги, `spans` у пианино, `lessons` у курса.

## Каталог материалов

```json
{
  "v": 1,
  "profiles": [{ "id": "anton", "name": "Антон", "hint": "пианино, книги, пастель" }],
  "materials": {
    "<id материала>": {
      "cover": true,
      "ach":   [{ "id": "…", "icon": "🔑", "name": "…", "hint": "…", "secret": false,
                  "when": [["page", ">=", 45]] }],
      "words": { "<id награды>": "текст, который показывается при получении" },
      "facts": [{ "t": "заголовок", "x": "текст", "more": ["…", "…"], "page": 45 }],
      "notes": [{ "ch": 1, "line": "1–10", "t": "заголовок", "x": "текст" }],
      "article":[{ "ch": 1, "t": "подзаголовок разбора" },
                 { "ch": 1, "h": "раздел" }, { "ch": 1, "p": "абзац" },
                 { "ch": 1, "note": "источник" }],
      "arts":   true
    }
  }
}
```

**Условия наград — данные, а не код.** `[["pct", ">=", 100], ["days", ">=", 20]]`, все
условия в списке по И. Операторы: `>= > <= < ==`, `is` (флаг), `has` (набор).
Метрики зависят от трека: у книги `page, pct, days, streak, maxJump, weekend, comeback,
reread`; у пианино `bars, pctR, pctL, pct, maxPass, maxRun, bothInOne`; у курса
`lessons, done, stepsDone, stages, minutes, maxAtOnce`. Наград на `notes` не делать — поле заметки из шторки
убрано, такие награды недостижимы.

**Карточки знаний** открываются по ходу: одна за занятие, у курса — по пройденным
урокам, с полем `page` — когда дочитал до страницы. Правило текста: контекст и история,
**без спойлеров сюжета**.

**Разборы и вопросы** живут не в каталоге, а в `article-<id>.json` того же гиста:
`{article: [{ch, t|h|p|note}], faq: [{ch, q, a}], notes: [...]}`. Каталог хранит
только флаг `arts: true`, а сам файл тянется, когда открываешь раздел, и остаётся
в localStorage (`keiko-art-<id>`). Иначе каждое исправление текста заставляло бы
телефон качать каталог целиком — он дорос до 660 КБ, из них 500 КБ разборы.

Карта открывается во весь экран: приближается щипком до шестидесяти крат,
точки не растягиваются вместе с картинкой (они лежат отдельным слоем и
считаются в экранных координатах), а слипшиеся точки раскладываются веером —
иначе четыре шетландских стека в двухстах метрах друг от друга навсегда
остаются одним кружком. В карточке места: поиск по картинкам, вопрос в Perplexity и карты — по
названию, если точка выверена, и по координатам, если поставлена на глаз.
Если у материала задан диапазон лет (`pastvu: {y, y2}` в файле разбора),
появляется «Старые фото»: приложение само запрашивает архив PastVu по
координате (`photo.giveNearestPhotos`, CORS открыт) и показывает ленту
миниатюр прямо у себя — год, подпись, крупный снимок и ссылка на источник.

Материал может иметь только карту, без разборов: тогда точки лежат с `ch: 0`,
кнопка на главной открывает карту сразу, а внутри работает поиск по названию.
Так сделаны «Столпы моря» — 106 стеков Тессона.

Третья вкладка — **карта мест**: `map: [{ch, name, lat, lon, t}]` и рамка
`mapBox: {west, east, north, south}` в том же файле, а сама картинка — отдельным
файлом `art-map-<id>.txt` (data URI, лениво, как обложки). Точки ставятся по
координатам в проекции Меркатора; карта собрана из тайлов OpenStreetMap, поэтому
в интерфейсе стоит подпись «карта © OpenStreetMap».

Раздел — список песней/глав со статусом
(прочитана, читаешь, впереди); внутри две вкладки: «Разбор» — статья, у каждого
абзаца кнопка «скопировать», и «Вопросы» — короткие ответы на «кто это вообще».
Обе закрыты, пока песнь не дочитана: в них пересказан сюжет целиком. Отметка
«разбор прочитан» ставится при открытии и хранится в `data.club`.

## Треки: книга, пианино, курс, видео

**Книга.** Два режима: `linear` — курсор по странице; `parts` — сборник, читаемый
вразнобой, прогресс считается покрытием отрезков (`spans`), иначе второй заход
выглядел бы откатом. У книги бывает `startPage` (начал с середины). Главы — список
`{name, from}`. «Завершить книгу» ставится вручную с главного экрана: прочитанная
книга уходит с ленты в архив и показывает прощальную статистику. Процент в библиотеке
считается от читаемой части, а не от корешка.

**Пианино.** Единица — такт. Пьеса режется на блоки не длиннее четырёх тактов;
внутри блока такты идут по кругу, и каждому нужно набрать десять заходов.
Заход отмечается одной из трёх кнопок — «легко», «с усилием», «сложно», — и под
каждым тактом стоят десять кружков, которые заполняются цветом захода. Когда все
такты блока набрали своё, блок играется целиком: «сложно» — повторяем, иначе
блок закрыт и начинается следующий. Процент — доля набранных заходов, прогноз
срока считается по ним же. Подробности и формат хранения — в [PRACTICE.md](PRACTICE.md).

**Курс (пастель).** Единица — урок: видео плюс задание. У урока может быть лесенка
шагов `steps` с таймкодами-диапазонами и конспектом на каждом этапе — владелец учится
через повтор действия, а не через пассивный просмотр. Конспект всегда раскрыт.

**Видео.** Отдельный материал на ролик: посмотрел — закрыт.

## Экраны и слои

Нижние вкладки: **Главная**, **Прогресс**, **Заметки**, **Захотелось** (плюс
«Таблетки» и «Какуля» в профиле Дианы). Экран «Достижения» остался в коде, но кнопки
на панели у него нет: награды и карточки видно в ленте, внутри той сессии, где они
открылись.

- **Главная** — лента обложек, кольцо процента, одна большая кнопка отметки, прогноз
  «в таком темпе примерно к…» и сколько дней ты уже занимаешься (именно дней занятий,
  не календарных). Фон перекрашивается под обложку. У книги рядом квадратная кнопка разбора — она есть только у
  материалов, где разбор действительно лежит в каталоге. Если ничего не трогать во время музыки — интерфейс уходит в «Погружение»,
  экран не гаснет (Wake Lock, а где его нет — играющее пустое видео).
- **Прогресс** — неделя или месяц: кольцо цели, плашки (такты, страницы, уроки),
  график, календарь. Плашки сравниваются **с целым прошлым периодом**, и под ними
  написано, с чем именно сравниваем.
- **Заметки** — лента мыслей и событий, лайки, фильтр любимых, «одна наугад».
  События (награда, завершённый материал, проведённое занятие) в случайную выборку
  не попадают.
- **Настройки** — отдельный экран разделами: профиль, синхронизация, цель, оформление,
  библиотека, карта знаний, пауза, данные, о приложении.

Оверлеи поверх всего: `#prac` (занятие по плану), `#kmap` (карта знаний на канве),
`.sheet` (шторка; `.sheet.full` — во весь экран, для чтения), `#cheer` (поздравление).

## Разделы одного профиля

`gutOn()` и `pillsOn()` включают вкладки только тем, у кого в id или имени есть
«diana/диана». **«Какуля»** — отметка самочувствия одним касанием, без анкеты и без
наград за пропуски. **«Таблетки»** — приняла утром и вечером, с временем; истории
намеренно нет: список пропусков превращает лекарство в упрёк. Это медицинские данные,
они уезжают только в её приватный файл.

## Скрипты в tools

```bash
python3 tools/material.py <id> <профиль>   # проверка материала перед словом «залито»
python3 tools/material.py --all
python3 tools/notes.py   <id> файл.txt     # комментарии к главам (--add дописывает)
python3 tools/article.py <id> файл1.txt …  # разборы песней из markdown
python3 tools/faq.py     <id> файл1.txt …  # вопросы и ответы к песням
python3 tools/map.py     <id> точки.txt [карта.jpg запад восток север юг]
python3 tools/museum.py  файл.txt          # артефакты, книга заменяется целиком
```

`material.py` проверяет поля книги, допустимые `art`/`tone`, порядок глав, наличие
обложки, уникальность наград, тексты к ним, достижимость условий, полноту карточек.
Все три скрипта **перечитывают гист прямо перед записью**.

## Релиз и проверка

Версия поднимается в трёх местах сразу:

```bash
# APP_VERSION в app.js, version в version.json, CACHE в sw.js
git push origin HEAD:main
```

Дальше GitHub Pages, и в приложении появляется баннер «Есть новая версия».

Перед словом «готово» — проверка в браузере, а не на глаз:

```bash
python3 serve.py 8473
```

Порядок, которым проверяли всё последнее время: зеркало проекта во временной папке
(сервер предпросмотра не видит `~/Documents`), открыть, подставить в консоли реальные
данные из гистов, вызвать нужную функцию, снять скриншот. `node --check app.js` —
обязательный минимум после любой правки скриптом.

## Правила, о которых просил владелец

- **Проверять и только потом говорить «залито».** Каждое «не работает» — это его
  отдельное сообщение и потерянный вечер.
- **Сухая подача спек**: компонент, параметры, код, поведение. Без лозунгов и
  уговоров.
- **Объяснять образно, а не упражнениями.** Справка о том, что играешь, — это узнавание
  и отчасти развлечение, а не задание.
- **Ничего чужого в репозиторий.** Перепечатанные комментарии из купленной книги,
  по-нотный разбор чужих произведений, записи собственной игры, фотографии — всё это
  живёт только в приватных гистах.
- **Разбор непрочитанной главы — спойлер.** Новые разборы делаются по мере чтения.

## Грабли, на которые уже наступали

- **Общий ETag на два профиля** — данные Дианы затирались данными Антона. Теперь
  всё по профилю: `gistEtagBy`, `syncNormBy`.
- **Запись по устаревшему снимку гиста.** Дважды: у Дианы пропал вечерний прогресс и
  заметки, в каталоге воскресли удалённые награды. Между чтением и записью успевает
  пройти чужая синхронизация — перечитывай файл прямо перед PATCH.
- **Удаление кода «по диапазону строк»** дважды роняло приложение: вместе с ненужной
  функцией уезжали соседние (`paceWhen`, `humanWhen`). Проверять надо не поиском по
  имени (он найдёт вызов и успокоит), а сверкой списка определений с `git show HEAD~1`.
- **Ключи прогресса, в которые зашиты границы окна.** Перенарезка пьесы обнуляла
  пройденное. Считай покрытие.
- **Ноль и равенство в трендах.** Показатель, исчезающий при нуле, и стрелка, которая
  не рисуется при равной разнице, читаются как поломка. Пиши «= столько же».
- **`entries()` после `render()`** — активный материал уже другой, и карточка сессии
  пропадала. Забирай значения до перерисовки.

# Как заводится новый материал

Пошагово: что нужно от книги, пьесы и курса, где что лежит, как устроены
награды, карточки знаний, артефакты и карта. Тон справок — по
[SPRAVKI.md](SPRAVKI.md), общие правила проекта — по [CLAUDE.md](CLAUDE.md).

Ничего из этого не живёт в репозитории: материал — это запись в приватном гисте
профиля плюс файлы в приватном гисте каталога.

- **профиль** `67442ecb9e18c230a93fad886b712c4f` → `keiko-anton.json`, `keiko-diana.json`
- **каталог** `8a3a280b21390e3b32569913f9f3cabe` → `keiko-catalog.json`, `museum.json`,
  `cover-<id>.txt`, `article-<id>.json`, `art-map-<id>.txt`, `audio-<id>.txt`,
  `keiko-practice.json`

Проверка в конце — `python3 tools/material.py <id> <профиль>`. Пока она красная,
говорить «залито» нельзя.

Материалы бывают четырёх видов, и различаются они только тем, чем меряется
продвижение:

| вид | где живёт | мера | что открывает предметы |
|---|---|---|---|
| **книга** | `book.books[]` | страницы | глава |
| **пьеса** | `piano.pieces[]` | такты и заходы | — |
| **курс-лекции** | `pastel.courses[]`, `mode: "watch"` | минуты просмотра | минута из `cues` |
| **курс по шагам** | `pastel.courses[]`, `plain: true` | шаги рисунка | номер шага |

Всё остальное — обложка, награды, карточки, артефакты, справки — устроено
одинаково.

---

## 1. Что нужно от материала

**Книга.** Обложка издания. Число страниц и с какой страницы начинается текст.
**Содержание** — список глав с номерами страниц: без него не будет ни «текущей
главы», ни привязки артефактов, ни карты по главам. Обычно оно есть в
предпросмотре магазина или в электронной версии. Издание и переводчик — они
попадут в подпись.

**Пьеса.** Обложка (издание нот или портрет). Число тактов. По-нотный разбор:
что играет правая, что левая, по тактам. Он тяжёлый и делается отдельно.

**Курс.** Обложка. Список занятий с длительностями — для лекций; список шагов,
разбитых на этапы, — для работы по шагам. Иллюстрации к шагам, если есть.

**Желательно для всех:** места с координатами — для карты; предметы, которые
можно пойти и увидеть, — для артефактов.

## 2. Запись книги в профиле

`book.books[]`:

```json
{
  "id": "odyssey",
  "title": "Одиссея",
  "author": "Гомер · перевод Григория Стариковского",
  "volume": "Носорог · Jaromir Hladik press",
  "pages": 464,
  "startPage": 0,
  "art": "wave",
  "tone": "wine",
  "cover": "covers/odyssey.jpg",
  "ratio": "510 / 720",
  "mode": "linear",
  "chapters": [{ "name": "Песнь I. Совет богов. Афина у Телемаха", "from": 7 }],
  "updatedAt": 1786172013276
}
```

- `pages` — последняя страница текста, не последняя страница тома.
- `startPage` — с какой страницы начинаешь. Книгу можно завести с середины:
  «Снег на траве» начат со 183-й, и процент считается от этого места.
- `chapters[].from` — страница, с которой глава начинается. Конец главы
  вычисляется сам: это `from` следующей минус один. Главы должны идти по
  возрастанию и не выходить за `pages`.
- `art` — рисунок на запасной обложке: `wave`, `pine`, `quill`, `lamp`.
- `tone` — цвет запасной обложки: `violet`, `sea`, `snow`, `night`, `wine`,
  `forest`, `pastel`.
- `ratio` — пропорция настоящей обложки, «ширина / высота» в пикселях
  оригинала. Без него обложка поедет.
- `mode` — `linear` (читаешь подряд, отмечаешь страницу) или `parts`
  (отмечаешь куски вразбивку, процент считается по покрытию).

## 3. Запись пьесы в профиле

`piano.pieces[]`:

```json
{ "id": "bwv853", "name": "Бах — Прелюдия es-moll, BWV 853", "author": "И. С. Бах",
  "bars": 40, "art": "keys", "tone": "violet",
  "cover": "covers/bwv853.jpg", "ratio": "509 / 720" }
```

- `bars` — число тактов. Из него считается всё: проценты, заходы, блоки.
- `art` — рисунок запасной обложки, у пьесы `keys`.

**По-нотный разбор** лежит отдельно, в каталоге, файлом `keiko-practice.json`:

```json
"bwv853": { "parts": [...], "legend": {...}, "hints": {...}, "runs": [...], "marks": {...} }
```

`hints` — по подсказке на такт, отдельно для правой и левой руки: что играть,
на какой счёт, какими пальцами. Это самая трудоёмкая часть и единственное, что
нельзя достать готовым. В репозитории его нет намеренно — это по-нотный разбор
чужого произведения.

Механика разбора: такт набирает **три захода** каждой рукой, блок из четырёх
тактов после этого требует **сшивку**, а после каждой сшивки — **прогон с
начала**. Отсюда и метрики наград.

## 4. Запись курса в профиле

`pastel.courses[]` — курсов может быть несколько, каждый показывается на
главной отдельным материалом.

```json
{ "id": "argos", "name": "Аргус", "author": "Бритон Ривьер",
  "plain": true, "top": "рисую", "note": "«Улисс и Аргус», Бритон Ривьер",
  "lessons": [ … ], "updatedAt": 1788… }
```

- `id` — первый курс исторически зовётся ключом `pastel`, остальные — своим id.
  От этого зависят награды, артефакты и ход разбора, поэтому id не меняют.
- `mode: "watch"` — курс-лекции: занятия смотрятся, отмечаются минуты.
- `plain: true` — курс по шагам: открыл и сразу шаг, без сетки занятий и без
  экрана подготовки.
- `top`, `note` — надписи на обложке сверху и под названием.

### Занятие-лекция

```json
{ "icon": "🐕", "title": "Собака: как она сделана", "dur": 6600,
  "cues": { "10": 2250, "35": 4147 } }
```

`dur` — длительность в секундах, из неё считается процент. `cues` — минуты, на
которых открываются артефакты: ключ это номер шага в исходной разметке,
значение — секунда ролика.

### Занятие по шагам

```json
{ "icon": "🏛", "title": "Аргус карандашом", "dur": 10800,
  "summary": "…", "stages": { "ЭТАП 1. Конструкция": "зачем этот этап" },
  "steps": [ { "g": "ЭТАП 1. Конструкция", "k": "do",
               "t": "Шаг 1. Крайние точки",
               "d": "текст шага с разметкой",
               "img": "argos-01", "iw": 998, "ih": 1400 } ] }
```

- `g` — этап, к которому относится шаг. Этапы собираются из шагов сами.
- `k` — вид шага: `do` (сделай сам), `note` (прочти), `watch`, `pause`, `read`.
- `t` — заголовок шага, `d` — тело.
- `img` — имя картинки в каталоге, файл `cover-<img>.txt`. `iw`/`ih` — её
  размеры: без них место под картинку резервируется наугад и текст прыгает.

**Разметка тела шага:** абзацы разделяются пустой строкой (переносы внутри
абзаца склеиваются), `- ` — список, `|…|…|` — таблица, тройные кавычки —
схема моноширинным блоком, `**жирное**`, `` `код` ``, строка целиком жирная —
подзаголовок, `> ` — врезка.

**Картинки шагов** пережимаются перед заливкой: фотографии — в WebP с
уменьшением до 1400 по длинной стороне, плоская графика — в WebP без потерь в
исходном размере. У двадцати иллюстраций «Аргуса» так вышло 7,6 МБ → 590 КБ.

---

## 5. Обложка

Фотография обложки, JPEG. Кладётся в каталог файлом `cover-<id>.txt` одной
строкой `data:image/jpeg;base64,…`, а в материале ставится `"cover": true`.

- **пропорция** — родная пропорция издания, она же в поле `ratio`;
- **размер** — по длинной стороне около 900 пикселей, вес до 250 КБ;
- **скругление, тень и наклон приложение делает само** — в картинку их
  запекать не надо, углы прямые.

## 6. Награды

Лежат в `keiko-catalog.json` → `materials.<id>.ach`. Это данные, а не код.

```json
{ "id": "raft", "icon": "🪵", "name": "Плот из двадцати брёвен",
  "hint": "Дочитать до пятой песни", "secret": false,
  "when": [["page", ">=", 96]] }
```

### Условие

`when` — список проверок, все должны сойтись. Формат `[метрика, оператор, значение]`,
операторы `>=`, `>`, `<=`, `<`, `==`, а ещё `is` (истина/ложь) и `has`
(значение есть в наборе).

**Общие для всех материалов:**

| метрика | что значит |
|---|---|
| `days` | сколько дней занимался — всего, не подряд |
| `pct` | процент материала |
| `weekend` | занимался в субботу или воскресенье |
| `comeback` | вернулся после недели перерыва |
| `notes` | оставлял заметку при отметке |

**Книга:**

| метрика | что значит |
|---|---|
| `page` | докуда дочитал |
| `maxJump` | самый большой заход в страницах |
| `reread` | сколько раз возвращался назад |

**Пьеса:**

| метрика | что значит |
|---|---|
| `touchedR`, `touchedL` | сколько тактов тронуто правой и левой |
| `firmR`, `firmL` | сколько тактов набрали заходы твёрдо |
| `pctR`, `pctL` | процент набранных заходов по руке |
| `pctFirm` | процент твёрдо выученного обеими руками |
| `maxPass` | самое большое число заходов на одном такте |
| `maxRun` | самый длинный прогон подряд, в тактах |
| `bothInOne` | обе руки за один заход |

**Курс:**

| метрика | что значит |
|---|---|
| `doneSet` | номера пройденных занятий, проверяется через `has` |
| `stageSet` | названия пройденных этапов, через `has` |
| `stepsDone` | сколько шагов рисунка закрыто |
| `stages` | сколько этапов пройдено целиком |
| `minutes` | сколько минут лекций отмечено |

### Три вида наград

1. **По месту в книге** — `page` или `pct`. Имя и значок из того эпизода, до
   которого дочитал: «Плот из двадцати брёвен», «Мяч у реки». Это основная
   масса, 15–25 штук на книгу.
2. **По поведению** — `days`, `weekend`, `comeback`, `maxJump`, `reread`.
   Их немного, 3–5.
3. **Тайные** — `"secret": true`. Не показываются до открытия, только силуэт.
   Пять-шесть на книгу, для того, что заранее обещать не хочется.

### Правила

- **id уникальны** внутри материала.
- **у каждой награды должен быть текст** в `words` (см. ниже) — иначе
  проверка ругается.
- **награда не должна быть недостижимой**: `page` не больше `pages`.
- Названий вроде «Молодец» и «Так держать» не бывает. Имя — это предмет или
  событие из книги. Подсказка `hint` говорит, что сделать, ровно и без
  уговоров: «Дочитать до пятой песни».
- **Спойлеров в именах нет.** Название не должно выдавать то, до чего человек
  ещё не дочитал.

### Тексты наград

`materials.<id>.words` — словарь `id награды → строка`. Это то, что
показывается в момент открытия, одной фразой, от лица события:

```json
"raft": "Плот связан из двадцати брёвен — единственный античный герой, показанный за ручной работой"
```

### Лестница дней

Общая для всех материалов, лежит в `materials.__common__.ach`: ступени
**3, 5, 10, 20, 30, 45, 60, 90, 120, 180, 270, 365 дней**. Считаются все дни,
подряд и вразбивку: пропуск ничего не отменяет. Наград за непрерывные серии в
приложении нет и не будет.

Книге нужны не все ступени: книга живёт три-четыре недели, и полугодовые
ступени висели бы мёртвыми. Поэтому у материала стоит потолок:

```json
"maxDays": 30
```

Потолки: книга — 30, курс-лекции — 30, рисунок — 60, пьеса — 365.

**Лестницу нельзя растягивать под размер книги.** Растянутая, она открывалась
бы одновременно с наградами за страницы — два имени для одного события. Время
отвечает на свой вопрос: сколько ты с этим живёшь. Поэтому её только обрезают.

### Свои имена ступеней

`materials.<id>.flavor` — те же ступени, но названные в мире книги:

```json
"flavor": {
  "d3":  { "icon": "🌅", "name": "Третий рассвет" },
  "d30": { "icon": "🌘", "name": "Месяц в море" }
}
```

Логика остаётся общей, меняются только слово и значок. Ступени без своего
имени показываются общим («Двадцать дней»).

### Путь

Отдельно от материалов есть `materials.__path__.ach` — дни, когда занимался
чем угодно, по всем материалам сразу. Книге он ничего не должен: это счёт
привычки, а не книги. Трогать его при заведении новой книги не надо.

## 7. Карточки знаний

`materials.<id>.facts`:

```json
{ "t": "Гостю не задают вопросов",
  "x": "У феаков чужака сначала кормят, моют и укладывают спать — и только потом спрашивают имя. Это не любезность, а закон: гостеприимство под защитой Зевса.",
  "more": ["Поищи слово «ксения» — греческое понятие гостевого союза"] }
```

- `t` — заголовок, короткий.
- `x` — три-четыре предложения. Проверка ругается на слишком короткие.
- `more` — один-два пункта «копнуть глубже»: что поискать, с чем сравнить.

### Как открываются

По счётчику: список делится поровну на число дней чтения. Прочитал N дней —
открылось N карточек. Если у карточки задана `"page": 96`, она открывается по
странице, а не по счётчику — так лучше, и так стоит делать всегда, когда
карточка привязана к месту.

### Чего в карточках быть не должно

- **Пересказа сюжета.** Карточка — контекст и история, а не содержание.
  Проверено на «Одиссее»: из тридцати карточек семнадцать оказались
  пересказом, и часть из них выдавала развязку раньше, чем человек до неё
  дочитал.
- **Спойлеров.** Открывается по счётчику — значит может прилететь когда
  угодно. Всё, что раскрывает узнавание, смерть, финал, — либо привязывать к
  странице, либо не писать вовсе.
- **Аннотации издательства.** Про перевод и издание хватает одной карточки.

Хорошая карточка отвечает на вопрос, который возник бы при чтении и полез бы
в поиск: что такое ксения, кто такой Ауэрбах, почему формулы повторяются.

## 8. Артефакты

`museum.json`, общий файл на все книги. Предмет:

```json
{ "id": "odyssey-1", "book": "odyssey", "ch": 1, "step": "",
  "name": "Статуя Юпитера", "inv": "ГР-4155",
  "museum": "Эрмитаж", "place": "Новый Эрмитаж, зал 107",
  "status": "Вживую", "kind": "скульптура",
  "why": "Песнь открывается советом богов: Зевс определяет, что Одиссею пора возвращаться.",
  "url": "https://hermitagemuseum.org/digital-collection/922851",
  "q": "Статуя Юпитера Эрмитаж", "img": "", "icon": "",
  "about": "Колоссальный мрамор конца I века…" }
```

| поле | что в нём |
|---|---|
| `book` | id материала |
| `ch` | номер главы. Открывается, когда до конца этой главы дочитал. Без `ch` открыт сразу |
| `name` | как называется предмет |
| `inv` | инвентарный номер, если есть |
| `museum`, `place` | где лежит и в каком зале |
| `status` | «Вживую», «В книге», «Приём», «в художественном магазине» |
| `kind` | вещь, картина, скульптура, место, книга, приём, материал, слово |
| `why` | одна фраза: почему он здесь, в этой главе |
| `url` | ссылка на карточку в собрании музея |
| `q` | поисковый запрос, если ссылки нет |
| `about` | справка, по [SPRAVKI.md](SPRAVKI.md) |

### Что годится в артефакты

- **вещи в музеях** — то, что упомянуто в книге и до чего можно доехать;
- **места** — с адресом и тем, как попасть;
- **книги и записи** — то, что можно открыть и прочитать;
- **понятия и приёмы** — без адреса, но с носителем: слово, правило, спор.

Норма — 25–50 предметов на книгу, по одному-два на главу.

Артефакт отличается от карточки знаний тем, что у него есть **носитель**:
предмет, книга, запись, место. Если носителя нет — это карточка. Если есть —
лучше артефакт: он привязан к главе и приходит вовремя.

## 9. Карта по главам

Отдельный файл каталога `article-<id>.json`. Он же держит разбор.

```json
{
  "map": [{ "ch": 1, "name": "Итака", "lat": 38.42, "lon": 20.68,
            "t": "Дом Одиссея, где всё начинается…",
            "q": "Ithaca island Greece",
            "about": "Имя догреческое, из греческого не выводится…" }],
  "mapBox": { "west": 8.6, "east": 30.9, "north": 42.2, "south": 30.4 },
  "mapVer": 1,
  "pastvu": { "y": 1826, "y2": 2000 }
}
```

- **`map[]`** — точки. У каждой глава, название, координаты, короткая подпись
  `t` и справка `about`.

### Два текста у точки, и они разные

Это важно и постоянно путается. У точки **два текста, и они отвечают на разные
вопросы**.

**`t` — что здесь происходит в книге.** Одно-два предложения, привязанные
именно к той главе, из которой точка взята. Это контекст: зачем герой здесь
оказался, что тут случилось. Плюс одна физическая деталь места, которая в
книге упомянута, — она сшивает текст с географией:

> Дом Одиссея, где всё начинается: женихи пируют, Телемах молчит. Остров
> невелик и горист — на нём почти нет ровной земли, и это в поэме подчёркнуто
> не раз.

Правила для `t`:

- **не забегает вперёд.** Точка открывается на своей главе; всё, что случится
  дальше, в подписи не упоминается;
- **не пересказывает главу.** Человек её только что прочёл;
- **связывает место и текст.** Если у места есть свойство, из-за которого в
  книге происходит именно это, — оно и есть содержание подписи;
- **два предложения, редко три.**

**`about` — справка о самом месте**, независимо от книги: откуда имя, что тут
на самом деле, что сейчас, как попасть. Четыре хода расписаны в
[SPRAVKI.md](SPRAVKI.md). Справка не повторяет `t` и вообще не пересказывает
книгу — она отвечает на то, с чем человек пошёл бы в поиск.

Разделение простое: **`t` — про эпизод, `about` — про место.** Если подпись
начинает объяснять, откуда взялось название, — она залезла в справку. Если
справка начинает рассказывать, что тут делал герой, — залезла в подпись.
- **`mapBox`** — географические границы картинки-подложки. Точки
  раскладываются по ней в проекции Меркатора, поэтому границы должны быть
  честными: соврёшь на градус — точки уедут.
- **`art-map-<id>.txt`** — сама подложка, картинка карты одной строкой
  `data:image/jpeg;base64,…`. Годится старинная карта региона: она и красивее,
  и честнее спутника, если действие происходит три тысячи лет назад.
- **`pastvu`** — годы, за которые к точкам подтягиваются старые фотографии с
  Pastvu. Для античности бессмысленно, для Петербурга — очень.

Точка появляется на карте, когда дочитал до её главы. Кнопка карты на главной
включается сама, если у книги есть и точки, и `mapBox`.

## 10. Разбор

В том же `article-<id>.json`:

- **`article[]`** — `{ ch, t }`: одна мысль на главу, заголовком.
- **`faq[]`** — `{ ch, q, a }`: короткие вопросы и ответы по главе. Кто такая
  Афина, что такое гекатомба. То, что мешает читать, если не знаешь.
- **`notes[]`** — `{ ch, line, t, x }`: комментарии к конкретным строкам.
  Самое трудоёмкое и самое ценное.

В материале ставится `"arts": true`, иначе приложение файл не запросит.

---

## 11. Атмосфера

`audio-<id>.txt` — короткий звук одной строкой `data:audio/…;base64,…`.
Играет только на главной, только когда материал открыт, и только по
разрешению. Не обязателен.

## 12. Проверка

```bash
python3 tools/material.py <id> <профиль>
```

Что она смотрит:

- книга есть в профиле, заполнены обязательные поля;
- `pages` больше нуля, `art` и `tone` из списка, `ratio` задан;
- главы идут по возрастанию и не выходят за пределы книги;
- материал есть в каталоге, есть файл обложки;
- награды есть, их id не повторяются;
- **у каждой награды есть текст в `words`**, и нет текстов без наград;
- нет наград, недостижимых по страницам;
- карточки есть и не слишком короткие.

Пока проверка не зелёная — книга не заведена.

## Чек-лист

**Книга**

```text
профиль    book.books[] — главы, pages, startPage, ratio, tone, art
каталог    materials.<id> — ach, words, facts, cover:true, arts:true,
           flavor на двенадцать ступеней, maxDays: 30
файлы      cover-<id>.txt
           article-<id>.json — article, faq, notes, map, mapBox, pastvu
           art-map-<id>.txt — подложка карты
музей      25–50 предметов в museum.json с book и ch
проверка   python3 tools/material.py <id> <профиль> — зелёная
```

**Пьеса**

```text
профиль    piano.pieces[] — bars, ratio, tone, art: "keys"
каталог    materials.<id> — ach, words, facts, cover:true,
           flavor, maxDays: 365
файлы      cover-<id>.txt, audio-<id>.txt по желанию
разбор     keiko-practice.json — parts, legend, hints, runs, marks
```

**Курс-лекции**

```text
профиль    pastel.courses[] — mode:"watch", занятия с dur и cues
каталог    materials.<id> — ach, facts, cover:true, flavor, maxDays: 30
файлы      cover-<id>.txt
музей      предметы с book:<id>, ch — номер занятия, step — номер шага из cues
```

**Курс по шагам**

```text
профиль    pastel.courses[] — plain:true, занятие со stages и steps,
           у шагов g, k, t, d, img, iw, ih
каталог    materials.<id> — ach, cover:true, flavor, maxDays: 60
файлы      cover-<id>.txt и cover-<img>.txt на каждую иллюстрацию
музей      предметы с book:<id>, ch:1, step — номер шага
```

## Что легко забыть

- **`words` на каждую награду.** Проверка ругается, и правильно: награда без
  текста открывается молча.
- **`ratio` у обложки.** Без него она поедет по пропорциям.
- **`iw`/`ih` у картинки шага.** Без них место резервируется наугад, и текст
  прыгает, когда картинка приезжает.
- **`arts: true`** — иначе приложение не запросит файл разбора и карты не будет.
- **Материал в описи каталога.** Обложка ищется только у известных описи
  материалов… точнее, искалась: теперь запрашивается в любом случае, но запись
  всё равно нужна — без неё не будет ни наград, ни карточек.
- **Спойлеры.** Ни в именах наград, ни в карточках, ни в подписях к точкам.
  Всё это открывается по счётчику или по главе и может прилететь раньше, чем
  человек дочитал.
- **Удаление — только пометкой.** Если выкинуть запись из списка в гисте,
  другое устройство вернёт её первой же синхронизацией.
